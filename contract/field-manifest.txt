# seam.api.v1 FIELD manifest — the SDK's declaration of the message-field surface it expects.
#
# WHY THIS FILE EXISTS
# --------------------
# `contract/rpc-manifest.txt` closed the "a new VERB landed and nobody wired it" hole. It is blind one
# level down: a new FIELD on an existing message passes every gate silently. That blindness is not
# hypothetical and has already cost two surfaces —
#
#   * `collective_outcome` regenerated in and sat unread, on DecisionResponse and then on SessionStep;
#   * the four ACDP D3 receipt slots plus P2 `retraction` landed on `ContextBinding` with CI green.
#
# So the expectation is a FILE, in both directions, per language — same shape as the RPC manifest:
#
#   * stub is MISSING a field listed here  -> a stale/partial generation, OR a field REMOVED from the
#                                             contract. The second is a breaking change; handle it,
#                                             never rewrite it away.
#   * stub has a field NOT listed here     -> something landed. DECIDE whether this SDK carries it,
#                                             then record the decision. That refusal IS the human
#                                             moment this gate exists to force.
#
# It is checked PER LANGUAGE, from the two generated stub trees read independently, so a stale ts/gen
# beside a fresh python/_gen is visible. Neither language is derived from the other.
#
# SPELLING
# --------
# One line per field: `<Message>/<field_name>`, proto spelling (snake_case), sorted, no tags, no types.
# A `map` field is ONE entry on its owner — `AuthorizeRequest/features` — never a key/value pair.
#
# WHICH SIDE `--write-manifest` WRITES FROM
# -----------------------------------------
# **Python**, exactly as the RPC manifest does. TypeScript is the cross-check, never the source. This
# matters: if the escape wrote from a side that cannot see every field, it would produce failures that
# the documented escape could never clear.
#
# THE PYTHON EXTRACTOR READS `*_FIELD_NUMBER`, **NOT** `__slots__`
# ----------------------------------------------------------------
# `ResumeRequest.raise` (tag 3) and `AdminResumeRequest.raise` (tag 6) are real fields. `raise` is a
# Python keyword, so the .pyi generator cannot put it in `__slots__` or in an attribute annotation —
# it emits only `RAISE_FIELD_NUMBER` and a `**kwargs` catch-all. Measured: `__slots__` yields 221,
# protobuf-es yields 223. A `__slots__`-derived manifest is therefore permanently red on two fields no
# escape hatch can clear, and — worse — blind to any future field named `class`, `from`, `import`,
# `global`, `lambda`, `pass`, `return`, `in`, `is`, `not` or `and`.
#
# SYNTHETIC MAP-ENTRY MESSAGES ARE EXCLUDED BY **NESTING**, NEVER BY NAME
# -----------------------------------------------------------------------
# Python's .pyi emits `AuthorizeRequest.FeaturesEntry` and `RunDecisionRequest.FeaturesEntry`, each
# with `key`/`value`; protobuf-es emits no type for either. Carried naively they are 2 messages x 2
# fields TypeScript can never produce — a permanently red gate. They are excluded structurally: a
# top-level class matches at column 0 and its own fields at exactly four spaces, so a nested class's
# fields (eight) are never collected.
#
# Filtering on the NAME `*Entry` would be a bug, not a shortcut: **`AuditEntry` is a real top-level
# `seam.api.v1` message** with two fields (`seq`, `decision_id`). A name filter drops it from BOTH
# sides — symmetric, so the gate stays green while going blind to a real message. That is the exact
# failure this manifest exists to prevent, reintroduced by the fix for a different one.
#
# WHAT THIS FILE DOES **NOT** CHECK
# ----------------------------------
# Names only. A field RETAGGED or RETYPED is a wire-breaking change and is invisible here, exactly as
# the RPC manifest records names and not signatures. `buf breaking` is what covers that; do not read a
# green gate here as wire compatibility.
#
# DECISIONS RECORDED HERE
# -----------------------
# `ContextBinding/{content_hash,receipt_hash,key_status,resolved_status}` (ACDP D3 receipt provenance,
# tags 7-10) and `ContextBinding/retraction` (ACDP P2, tag 11) are **DECLARED AND DELIBERATELY NOT
# INTERPRETED**. This gate refused them first — exit 6, naming all five in both languages — and this
# is the decision that refusal forced, not a silent adoption:
#
#   * They are CARRIED, not read. `resolve_context` returns `pb.ContextBinding` directly, so the five
#     appear on the generated type with no wrapper needed and a caller can already see them.
#   * This SDK does not compute `context_digest` and `verify/src/verify.rs` does not read these slots,
#     so there is nothing here that could interpret them correctly yet.
#   * `key_status` is a CLOSED, PascalCase vocabulary; `resolved_status` is an OPEN, lowercase one.
#     Both are byte-identical to what enters the digest preimage, so any SDK-side re-spelling —
#     case-folding, normalising, mapping to an enum — silently breaks third-party digest recomputation.
#     Declaring them without interpreting them is what keeps that from happening by accident.
#
# Phase 9 of `plans/post-adoption-hardening-and-acdp-readiness.md` settled this rather than
# reversing it: the fields are carried and never wired. `verify/` does not compute
# `context_digest`, so there is nothing here to check a receipt slot against, and a projection
# would create a second spelling of a wire commitment for no verification gain.
#
# TO REGENERATE (after deciding, not before):
#     scripts/check-contract.sh --write-manifest

# ENUM-VALUE MANIFEST — the same discipline, one level below a FIELD
# --------------------------------------------------------------------
# `buf breaking` in seam-runtime (`.github/workflows/ci.yml:168-176` there) treats an ADDITIVE enum
# value as a compatible change and passes it BY DESIGN — proto3 enums are open by convention, so
# nothing upstream refuses a new `COLLECTIVE_VERDICT_VETOED` landing on the wire. This SDK does not get
# that convention for free: `python/seam_sdk/_collective.py:19` and `python/seam_sdk/errors.py:104` are
# deliberately fail-closed and raise `UnknownCollectiveVerdictError` on any value they do not
# recognise. So a legitimate, additive, buf-breaking-approved runtime change reaches this SDK's
# consumers as a hard error on a real response — the exact "value stored twice, one copy stale"
# failure the FIELD manifest above exists to catch, one layer down the same message.
#
# Declared here for the same three reasons the FIELD manifest is: it is a second, independently
# derived copy of the surface (read from generated stubs, never from the .proto source, for the same
# reason as the field extractors — the stubs are what this SDK actually compiles against, not what the
# stubs merely claim to come from); it is checked in BOTH directions (a value the manifest expects and
# the stubs lack is stale generation or a REMOVED value; a value the stubs carry and the manifest does
# not is a new one nobody has decided about yet); and it is checked PER LANGUAGE, independently, so a
# stale ts/gen beside a fresh python/_gen cannot vouch for it.
#
# SPELLING, AND WHY IT SHARES THIS FILE RATHER THAN A SECOND ONE
# -----------------------------------------------------------------
# `<Enum>#<VALUE>`. `#` cannot occur in a proto message name, field name, or enum/value name, so a
# single flat manifest stays unambiguously partitioned between the FIELD lines above (`<Message>/
# <field>`, never a `#`) and the ENUM lines below (always exactly one `#`), with no separator
# collision. It also does not collide with this file's own comment convention: a comment is a line
# whose FIRST non-whitespace character is `#` (`grep -vE '^\s*(#|$)'`, the filter both
# `manifest_fields` and `manifest_enums` in scripts/check-contract.sh apply before doing anything
# else) — an enum line like `AuthorizeVerdict#ALLOW` begins with a letter, so it survives that filter
# exactly like a field line does, and the two `manifest_*` readers then split what remains by whether
# `#` appears in it at all. Rejected: a separate `contract/enum-manifest.txt` — a second file is a
# second thing to forget to update; this file is already the one declaration of "the surface this SDK
# expects."
#
# WHERE THE VALUES COME FROM (READ THE GENERATED STUB, NEVER THE .proto)
# ---------------------------------------------------------------------
# Python: `python/seam_sdk/_gen/seam/api/v1/seam_pb2.pyi`, the `<VALUE>: _ClassVar[<Enum>]` lines
# under each `class <Enum>(int, metaclass=_enum_type_wrapper.EnumTypeWrapper):`. TypeScript:
# `ts/gen/seam/api/v1/seam_pb.ts`, the `@generated from enum value: <VALUE> = <n>;` doc comment — read
# from the GENERATOR'S OWN record of the contract, not the TS identifier, because protobuf-es strips
# the enum's common prefix from `AuthorizeVerdict`'s bare TS members (`ALLOW`, not
# `AUTHORIZE_VERDICT_ALLOW`) and could reformat the identifier without the contract itself changing;
# the doc comment cannot drift from the wire value the way the surrounding TypeScript syntax could.
#
# `UNSPECIFIED` ZERO VALUES ARE DECLARED, NOT FILTERED
# --------------------------------------------------------
# A runtime removing the zero value is exactly as real a breaking change as removing any other one —
# more so here, since `AuthorizeVerdict`'s and `CollectiveVerdict`'s own doc comments make
# `UNSPECIFIED` the mandatory fail-safe default a client MUST route to on anything it does not
# recognise. Filtering it out would make the gate blind to the one value every OTHER value's
# fail-closed behaviour depends on still meaning "unspecified."
#
# GENERATION SKEW IS REPORTED SEPARATELY FROM MANIFEST DRIFT
# ----------------------------------------------------------
# If Python's stubs carry a value TS's do not (or the reverse), that is NOT "the manifest is stale" —
# both languages regenerate from the same contract in the same push, so a value present in one and
# absent from the other means one tree's generation went stale while the other's did not.
# `--write-manifest` writes only from Python (below), so this class of failure would otherwise
# silently pass through the escape hatch as if it were an ordinary manifest update.
# `scripts/check-contract.sh` reports it under its own "GENERATION SKEW" heading, distinct from
# MISSING/NOT IN THE MANIFEST, so it is never mistaken for a decision to make.
#
# NO ENUM IS NESTED INSIDE A MESSAGE TODAY — GUARDED, NOT ASSUMED FOREVER
# ----------------------------------------------------------------------
# The extractors track "current enum" the same structural way the field extractors track "current
# message" — a nested one would vanish from BOTH sides at once, symmetrically, and the gate would stay
# green while going blind to it, the same trap the FIELD manifest's map-entry exclusion above warns
# about. `scripts/check-contract.sh` asserts none exist and exits loud, not silently, the first time
# one does.
#
# WHICH SIDE `--write-manifest` WRITES FROM
# ------------------------------------------
# Python, same as the FIELD section and the RPC manifest, appended to the SAME file after the field
# lines. TypeScript is the cross-check, never the source, for the same reason as the field manifest.
#
